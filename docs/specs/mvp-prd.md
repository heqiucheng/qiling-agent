# 企灵 Agent MVP PRD

**状态**：Approved for UI Design  
**版本**：v0.1  
**日期**：2026-05-28  
**产品名**：企灵 Agent / Qiling Agent  
**仓库**：https://github.com/heqiucheng/qiling-agent

## 1. 背景

企灵 Agent 是面向企业微信私域销售团队的自动跟进与复盘智能体。第一版不做大而全 CRM，也不做完全自动发送，而是聚焦一个可验证、可演示、可持续扩展的核心闭环：

```text
客户数据进入系统
-> Agent 自动分析客户
-> Agent 自动生成待确认话术
-> 销售确认后复制发送
-> 系统记录反馈
-> Agent 生成复盘和改进建议
```

项目采用规则先行的 AI 协作方式：`AGENTS.md` 作为恒定规则蓝图，后续开发必须将评审、测试、Lint、构建纳入 AI 工作流约束，持续通过反馈优化项目规则，避免不可维护代码。

## 2. 产品定位

企灵 Agent 是企业微信私域销售自动跟进与复盘 Agent。它不是一个需要销售主动提问的 AI 聊天工具，而是一个会主动分析客户状态、生成待确认话术、沉淀客户画像、统计销售过程并输出复盘建议的销售执行系统。

一句话介绍：

```text
企灵 Agent 自动识别客户机会、生成销售话术并创建待确认跟进任务，让销售只需确认关键动作。
```

## 3. 目标用户

### 3.1 一线销售

一线销售每天需要跟进大量企业微信客户，核心痛点是：

- 客户很多，不知道先跟谁。
- 不知道怎么回复客户更合适。
- 容易忘记沉默客户和高意向客户。
- 复盘依赖人工回忆，无法持续优化话术。
- 希望 AI 自动准备好话术，自己确认后复制发送。

### 3.2 销售主管

销售主管需要快速了解团队客户质量和执行情况，核心痛点是：

- 不知道哪些客户有机会。
- 不知道哪些客户长时间没人跟。
- 不知道销售话术和跟进动作有没有问题。
- 缺少按客户阶段、意向、风险聚合的复盘。
- 希望系统自动给出团队问题和下一步建议。

## 4. 业务目标

第一版目标是验证企灵 Agent 的核心价值：

- 销售能通过上传聊天记录或企业微信数据获得可用话术。
- 销售每天能看到明确的待确认跟进任务。
- 客户画像、意向判断和推荐话术有明确理由。
- 主管能看到客户机会、风险客户和销售改进建议。
- 系统能记录话术采纳、跳过、修改和标记不准等反馈。

## 5. 成功指标

MVP 阶段关注以下指标：

| 指标 | 说明 | MVP 目标 |
| --- | --- | --- |
| 聊天记录解析成功率 | 上传或粘贴记录能被结构化解析的比例 | >= 80% |
| 话术生成成功率 | 有效客户上下文下成功生成推荐话术的比例 | >= 90% |
| 话术复制率 | 生成话术被销售复制的比例 | >= 30% |
| 标记不准率 | 销售认为 Agent 判断不准的比例 | <= 30% |
| 复盘可用性 | 复盘中心能指出具体客户机会、风险和建议 | 可人工验收 |
| 主流程完成时间 | 从上传聊天记录到复制话术的时间 | <= 2 分钟 |

## 6. MVP 范围

### 6.1 必须包含

- 账号与角色：销售、主管。
- 客户管理：客户列表、客户详情、阶段、意向等级、负责人。
- 聊天记录上传或粘贴。
- 聊天记录解析。
- 客户画像自动生成。
- 客户阶段识别。
- 意向等级判断。
- 推荐话术生成。
- 推荐理由和风险提示。
- 待确认跟进任务。
- 一键复制话术。
- 任务反馈：已复制、换一种、跳过、标记不准。
- 复盘中心。
- 基础统计。
- Agent 执行记录。

### 6.2 简化实现

- 企业微信接入第一版可以先做配置入口、数据结构预留和手动导入链路。
- 如果企业微信接口权限尚未准备好，上传或粘贴聊天记录作为可运行主链路。
- 主管看板先做核心指标和建议，不做复杂 BI。
- 权限先支持销售和主管两个角色。

### 6.3 不做范围

第一版不做：

- 完全自动发送客户消息。
- 完整 CRM 替代能力。
- 复杂审批流。
- 多企业租户商业化后台。
- 复杂组织架构。
- 移动端 App。
- 小程序。
- 全行业通用 Agent 平台。

## 7. 核心用户场景

### 7.1 场景一：上传聊天记录并生成话术

用户：一线销售。

流程：

```text
销售上传或粘贴企业微信聊天记录
-> 系统解析客户、销售、时间、消息内容
-> Agent 生成客户画像、意向等级、当前阶段、主要顾虑
-> Agent 生成推荐跟进话术、理由和风险提示
-> 销售复制话术到企业微信发送
-> 系统记录话术被采纳
```

验收标准：

- 支持粘贴聊天文本。
- 支持上传 `.txt`、`.csv`、`.xlsx`、`.docx` 中至少一种格式，MVP 可优先 `.txt` 和 `.csv`。
- 解析失败时必须提示原因和修复建议。
- 销售能在解析后确认或修正客户名称、销售名称和消息归属。
- 生成话术必须可复制。

### 7.2 场景二：工作台查看今日待确认任务

用户：一线销售。

流程：

```text
销售打开工作台
-> 系统展示今日待确认话术、高意向客户、沉默客户、风险客户
-> 销售查看某条任务
-> 销售看到推荐原因、话术和风险提示
-> 销售复制、换一种、跳过或标记不准
```

验收标准：

- 工作台第一屏必须显示“今天该做什么”。
- 每个任务必须包含客户、阶段、意向、推荐动作、推荐话术、推荐理由。
- 复制成功必须有明确反馈。
- 换一种话术不能丢失原任务上下文。
- 标记不准必须记录反馈原因入口。

### 7.3 场景三：查看客户详情

用户：一线销售、销售主管。

流程：

```text
用户进入客户详情
-> 查看客户资料、客户画像、聊天记录、当前阶段、意向等级
-> 查看 Agent 推荐和历史跟进任务
-> 查看销售反馈和风险提示
```

验收标准：

- 客户详情必须展示完整上下文。
- Agent 判断必须展示理由，不允许只展示结论。
- 推荐话术和历史任务必须能追溯。
- 主管可以看到团队客户，销售只能看到自己的客户。

### 7.4 场景四：主管查看复盘中心

用户：销售主管。

流程：

```text
主管进入复盘中心
-> 查看客户分层、风险客户、话术效果、跟进效率
-> 查看 Agent 总结的问题和建议
-> 找到需要主管介入的客户
```

验收标准：

- 复盘中心必须展示客户机会和风险，而不只是数字。
- 每条建议必须能关联到客户、话术或销售动作。
- 数据不足时必须提示“样本不足”，不能制造精确假象。

## 8. 核心页面

### 8.1 工作台

目标：让销售一打开就知道今天该做什么。

内容：

- 今日待确认话术。
- 高意向客户。
- 沉默待唤醒客户。
- 流失风险客户。
- 今日复盘摘要。

操作：

- 查看推荐原因。
- 复制话术。
- 换一种话术。
- 跳过。
- 标记不准。
- 进入客户详情。

### 8.2 客户列表

内容：

- 客户姓名或昵称。
- 来源。
- 负责人。
- 当前阶段。
- 意向等级。
- 最后沟通时间。
- 待跟进状态。
- 主要顾虑。

筛选：

- 搜索客户。
- 按阶段筛选。
- 按意向筛选。
- 按风险筛选。
- 按负责人筛选。

### 8.3 客户详情

内容：

- 客户画像。
- 聊天记录。
- Agent 判断结果。
- 推荐话术。
- 历史跟进任务。
- 销售反馈。
- 风险提示。

### 8.4 数据接入

内容：

- 企业微信配置入口。
- 上传聊天记录。
- 粘贴聊天记录。
- 上传解析结果确认。
- 解析失败提示。

### 8.5 复盘中心

内容：

- 客户机会。
- 风险客户。
- 话术效果。
- 跟进效率。
- 客户阶段分布。
- Agent 改进建议。
- 主管介入建议。

## 9. 客户阶段与标签

### 9.1 主阶段

每个客户只能有一个主阶段：

```text
新线索
已破冰
需求了解
产品了解
价格/方案异议
强意向
待促单
已成交
沉默
流失风险
```

### 9.2 标签

客户可以有多个标签：

```text
价格敏感
关注售后
需要案例
决策人不明确
竞品对比中
预算不足
时间紧急
复购可能
转介绍可能
投诉风险
```

## 10. 话术类型

第一版支持以下话术：

- 破冰话术。
- 需求挖掘话术。
- 产品介绍话术。
- 价格异议话术。
- 案例证明话术。
- 促单话术。
- 沉默唤醒话术。
- 复购话术。
- 转介绍话术。
- 投诉安抚话术。

每条话术至少包含：

- 推荐话术。
- 推荐理由。
- 适用场景。
- 风险提示。
- 可替换版本。

## 11. Agent 输出结构

Agent 不允许只输出一段自然语言。必须输出结构化结果，便于前端展示、后端存储和测试验证。

示例：

```json
{
  "customer_stage": "价格/方案异议",
  "intent_level": "high",
  "main_concerns": ["价格", "效果", "售后"],
  "recommended_action": "解释方案价值并引导预约",
  "script": "您好，刚才您提到比较关注价格，我这边帮您整理了一下更适合您的方案...",
  "reasoning": "客户连续两次询问价格和售后，说明有购买兴趣但存在决策顾虑。",
  "risk_flags": ["涉及价格承诺，建议人工确认"],
  "next_followup_time": "今天 16:00 前"
}
```

## 13. 统计指标

第一版复盘指标：

- 客户总数。
- 高意向客户数。
- 今日待跟进客户数。
- 超时未跟进客户数。
- 沉默客户数。
- 流失风险客户数。
- 话术生成数。
- 话术复制数。
- 话术采纳率。
- 换一种次数。
- 标记不准次数。
- 客户回复率。
- 阶段推进数。

指标必须服务动作决策，回答：

```text
今天最该跟谁？
哪些客户快流失？
哪些话术有效？
销售哪里没跟上？
主管该介入哪里？
```

## 14. 权限要求

MVP 角色：

| 角色 | 权限 |
| --- | --- |
| 销售 | 查看自己的客户、任务、话术和复盘；上传聊天记录；复制话术；提交反馈 |
| 主管 | 查看团队客户、任务、统计和复盘；查看需要介入的客户；查看销售执行情况 |

权限原则：

- 销售只能看自己的客户。
- 主管可以看团队客户。
- 后续预留管理员角色。
- 客户数据和聊天记录必须为后续租户隔离预留边界。

## 15. 风险边界

### 15.1 AI 误判风险

控制方式：

- 所有 AI 推荐必须展示理由。
- 所有 AI 推荐必须展示风险提示。
- 第一版只复制发送，不自动发给客户。
- 销售可以标记不准。
- Agent 执行记录必须可追溯。

### 15.2 企业微信接口风险

控制方式：

- 保留企业微信接入设计。
- 上传或粘贴聊天记录作为可运行主链路。
- 企业微信同步作为后续增强，不阻塞 MVP。

### 15.3 需求膨胀风险

控制方式：

- 不做完整 CRM。
- 不做自动发送。
- 不做复杂多租户商业化能力。
- 不做全行业 Agent 平台。
- 先把私域销售跟进和复盘闭环跑通。

### 15.4 高风险内容

以下内容必须人工确认：

- 价格承诺。
- 优惠政策。
- 合同条款。
- 退款相关。
- 投诉处理。
- 医疗、金融、法律等敏感行业内容。
- 任何可能影响客户信任的确定性承诺。

## 16. MVP 演示验收路径

第一版完成后必须跑通以下路径：

```text
1. 用户登录系统。
2. 上传一段企业微信聊天记录。
3. 系统解析出客户和聊天内容。
4. Agent 生成客户画像、阶段、意向等级。
5. Agent 生成一条推荐跟进话术。
6. 用户能查看推荐理由和风险提示。
7. 用户点击复制话术。
8. 系统记录该话术被采纳。
9. 复盘中心出现该客户的机会、风险和建议。
10. 主管能看到客户分层和跟进建议。
```

## 17. UI 设计输入

UI 设计阶段需要优先产出以下页面：

1. 工作台。
2. 客户列表。
3. 客户详情。
4. 待确认话术任务区。
5. 数据接入。
6. 复盘中心。
7. 登录页和基础布局。

UI 设计原则：

- 第一屏展示任务和机会，不做营销页。
- 信息密度适合销售日常工作。
- 每个 AI 推荐都要展示理由和风险。
- 主要操作是复制、换一种、跳过、标记不准。
- 空状态要引导上传聊天记录或配置企业微信。
- 页面风格应企业级、克制、清晰、高效。
