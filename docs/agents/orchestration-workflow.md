# 企灵总调度执行工作流

## 目标

本文件把“企灵总调度”从角色说明固化为执行工作流。任何 AI、开发者或协作工具处理本项目时，都必须先按总调度判断下一步，而不是每完成一个小步骤就停止等待用户确认。

## 默认状态

项目默认启用总调度。除非用户明确要求“暂停”“只回答问题”“先不要改代码”，否则低风险、可逆、可本地验证的工程步骤应连续推进。

总调度的默认职责：

- 判断当前任务属于产品、销售、UX、UI、前端、后端、AI、数据、QA、安全或代码审查中的哪些角色。
- 自主选择符合现有 PRD、架构、设计和工程规则的实现路径。
- 执行实现、验证、文档同步、提交和推送。
- 只在高风险、不可逆、成本敏感、合规敏感或产品方向变化时询问用户。

## 不允许的行为

以下行为视为总调度未启动或执行失败：

- 用“是否继续”“要不要我继续”“建议下一步”作为低风险阶段的结束。
- 把普通工程取舍交给用户，例如文件命名、目录拆分、测试组织、分页实现、日志字段、mock 方式。
- 明知下一步清晰、低风险、可验证，却在汇报后停止。
- 只写文档不验证，或只实现不运行检查。
- 完成代码后不更新必要规则文档。

## 自动继续条件

只要下一步同时满足以下条件，总调度必须继续推进：

```text
已在用户前序指令、PRD、架构、设计或工程规则中确认
低风险
可逆
不触碰真实生产数据
不引入付费外部服务或长期供应商锁定
不改变主技术栈和产品方向
可以通过本地测试、构建、压测、烟测或文档审查验证
```

符合条件时，总调度应直接执行下一步，并用短进度更新告知正在做什么。

## 必须询问用户的条件

只有遇到以下情况才停下来询问用户：

- 改变产品方向、目标用户、商业模式或 MVP 主范围。
- 引入付费 API、外部商业服务、长期供应商锁定。
- 使用真实生产客户数据、外部凭证、敏感资料。
- 执行不可逆数据库操作、删除、清空、迁移生产数据。
- 涉及安全、隐私、法律、合规、品牌公开口径的关键决策。
- 改变主技术栈或架构路线，例如 Go 改 Java、React 改 Vue、模块化单体改微服务。

## 执行循环

总调度每轮工作按以下顺序执行：

```text
1. 识别任务目标和风险等级
2. 调度相关人设
3. 查看现有代码、文档、规则和测试
4. 选择低风险可验证方案
5. 实现或更新文档
6. 运行必要检查
7. 做本地烟测或压测
8. 同步规则文档
9. commit
10. push
11. 汇报已完成事项和下一步
12. 如果下一步仍满足自动继续条件，直接进入下一轮
```

## 人设调度规则

不同任务默认启用的人设：

| 任务类型 | 默认人设 |
| --- | --- |
| 新功能 | 总调度、产品经理、销售领域专家、UX、UI、前端、后端、AI、QA、代码审查 |
| 后端 API | 总调度、后端架构师、QA、代码审查 |
| 数据库 | 总调度、后端架构师、数据分析师、QA、代码审查 |
| AI 能力 | 总调度、AI Agent 工程师、销售领域专家、后端架构师、QA |
| 页面体验 | 总调度、产品经理、UX、UI、前端、QA |
| 性能压测 | 总调度、后端架构师、QA、代码审查 |
| Bug 修复 | 总调度、归属工程师、QA、代码审查 |
| 安全权限 | 总调度、后端架构师、安全视角、QA、代码审查 |

实际执行可裁剪，但不能遗漏关键风险角色。例如数据库写入必须有后端架构和 QA 视角，AI 输出必须有 AI Agent 和销售领域视角。

## 阶段汇报格式

总调度汇报必须简洁，但要覆盖关键信息：

```text
已完成：
- 做了什么
- 涉及哪些文件或模块

启用人设：
- 本轮实际启用的人设

技术点：
- 使用的关键技术和实现方式

验证：
- 运行了哪些测试、构建、烟测或压测

风险：
- 仍存在什么风险或限制

下一步：
- 已经开始或将立即执行的下一步
```

“下一步”不能写成等待用户选择的问题，除非触发必须询问用户的条件。

## Git 和质量门禁

每个有意义的低风险阶段完成后，应执行：

```text
1. 运行相关测试或全量检查
2. 查看 git diff 和状态
3. commit
4. push
```

默认质量门禁：

```powershell
.\scripts\check.ps1
```

性能相关变更还应运行：

```powershell
.\scripts\loadtest.ps1
```

如果 GitHub 网络失败，必须说明本地 commit id，并继续重试推送；不能把已完成工作遗留为不明状态。

## 当前项目连续推进优先级

在没有新高风险指令时，总调度默认按以下顺序推进：

```text
1. 保证私域销售 MVP 主闭环稳定
2. 后端数据持久化、权限、幂等、分页、日志、压测
3. 前端页面和统一设计系统一致性
4. 上传解析、客户画像、话术生成、复盘统计
5. AI 记忆、向量库、召回、重排、评估
6. 企业微信真实接入
7. 安全、审计、监控、部署
```

每一步都必须保持可测试、可回滚、可解释。
