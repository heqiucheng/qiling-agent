# 企灵 Agent 后端工程规范

**状态**：Hard rules for implementation  
**版本**：v0.1  
**日期**：2026-05-28  
**适用范围**：后端服务、API、数据库访问、Agent 服务、企业微信接入、统计和复盘模块

## 1. 目标

后端代码必须长期可维护、可测试、可扩展，不能为了快速实现把逻辑堆进单个文件或单个函数。企灵 Agent 涉及客户资料、聊天记录、AI 判断、销售跟进和复盘统计，后端必须从第一天就保持清晰边界。

核心目标：

```text
统一风格
分层清晰
职责单一
可测试
可观测
高性能
安全可控
可持续演进
```

## 2. 硬性规则

### 2.1 禁止单文件堆逻辑

禁止把以下内容塞进同一个文件：

```text
路由注册
请求参数解析
权限判断
业务逻辑
数据库查询
第三方接口调用
AI Prompt 拼接
响应格式组装
```

任何文件如果持续变长，必须优先拆分职责。单文件原则上不应超过 300-500 行；超过时必须评估是否拆分。

### 2.2 必须分层

后端默认采用模块化单体，但模块内部必须分层：

```text
handler/controller：处理 HTTP 输入输出
service/usecase：编排业务流程
domain：领域模型、业务规则、状态流转
repository/store：数据库访问
integration/client：第三方系统封装，如企业微信、LLM、向量库
job/worker：异步任务
schema/dto：请求、响应、内部数据结构
```

控制器不能直接写复杂业务逻辑，业务服务不能直接拼 HTTP 响应，数据库访问不能散落在各处。

### 2.3 模块边界清晰

推荐模块：

```text
auth
users
customers
conversations
uploads
agent
followup_tasks
script_recommendations
review_reports
integrations/wecom
audit_logs
```

跨模块调用必须通过明确接口，不允许随意读写其他模块内部数据结构。

### 2.4 统一代码风格

项目一旦选定后端技术栈，必须同时确定：

```text
目录结构
命名规范
错误格式
日志格式
接口响应格式
分页格式
时间格式
ID 格式
测试组织方式
```

禁止今天一种返回结构，明天另一种返回结构。

统一响应示例：

```json
{
  "data": {},
  "error": null,
  "meta": {
    "request_id": "req_xxx",
    "timestamp": "2026-05-28T10:00:00Z"
  }
}
```

统一错误示例：

```json
{
  "data": null,
  "error": {
    "code": "CUSTOMER_NOT_FOUND",
    "message": "客户不存在或无权访问",
    "details": {}
  },
  "meta": {
    "request_id": "req_xxx",
    "timestamp": "2026-05-28T10:00:00Z"
  }
}
```

## 3. 注释规则

### 3.1 必须注释的地方

需要写注释：

- 复杂业务规则。
- 客户阶段流转规则。
- 意向评分规则。
- 权限边界。
- 数据一致性处理。
- 幂等处理。
- 企业微信接口特殊限制。
- AI 输出校验和降级逻辑。
- 性能优化原因。

### 3.2 不该写的注释

避免无意义注释：

```text
// 设置用户 ID
// 查询数据库
// 返回结果
```

注释要解释“为什么这样做”，不是重复代码本身。

## 4. 性能规则

### 4.1 数据库

必须注意：

- 常用查询必须有索引设计。
- 客户列表、聊天记录、任务列表必须分页。
- 禁止 N+1 查询。
- 大文本聊天记录和 AI 输出要考虑存储大小和读取范围。
- 统计查询要避免每次实时扫全表。
- 复盘报表可以采用缓存或异步聚合。

### 4.2 API

目标：

```text
普通列表接口 P95 < 300ms
详情接口 P95 < 500ms
AI 生成类接口允许异步处理
上传解析类接口必须有进度状态
```

AI、上传、企业微信同步等慢任务不能长期阻塞普通请求。

### 4.3 异步任务

以下任务优先异步化：

```text
聊天记录解析
客户画像生成
话术生成
复盘报告生成
企业微信同步
向量化入库
统计聚合
```

## 5. 异常和边界情况

每个接口必须考虑：

```text
参数缺失
参数类型错误
权限不足
资源不存在
重复提交
第三方接口超时
第三方接口限流
AI 输出不合法
数据库写入失败
上传文件过大
上传文件格式不支持
聊天记录解析为空
客户归属冲突
```

用户可见错误必须给出下一步动作，例如：

```text
聊天记录解析失败，请检查是否包含时间、发送人和消息内容。
企业微信同步失败，请检查 CorpID、Secret 和通讯录权限。
```

## 6. 安全规则

必须遵守：

- 客户数据和聊天记录必须支持租户隔离。
- 销售只能访问自己的客户。
- 主管只能访问团队客户。
- 企业微信凭证必须加密保存。
- 日志不能输出敏感凭证、完整聊天记录或客户隐私。
- 上传文件必须限制大小、格式和解析方式。
- 所有写操作必须记录关键审计日志。
- AI 生成结果不能直接触发高风险外部动作。

## 7. 测试要求

### 7.1 必须测试

每个后端模块至少覆盖：

```text
正常路径
空数据
非法输入
权限不足
资源不存在
重复提交
第三方失败
AI 输出异常
数据库错误或事务回滚
```

### 7.2 测试类型

必须逐步建立：

```text
单元测试：领域规则、评分规则、解析规则
接口测试：API 参数、权限、响应格式
集成测试：数据库、企业微信 mock、LLM mock
回归测试：核心演示路径
压力测试：列表、上传、解析、统计、Agent 任务队列
```

### 7.3 压力测试

需要压测的关键路径：

- 客户列表分页和筛选。
- 客户详情和聊天记录读取。
- 批量上传聊天记录。
- 批量生成客户画像。
- 批量生成话术任务。
- 复盘中心统计。
- 企业微信同步任务。

压测必须记录：

```text
并发数
数据量
P50/P95/P99 延迟
错误率
CPU/内存
数据库慢查询
队列积压
```

## 8. 可观测性

必须具备：

```text
request_id
结构化日志
关键业务事件日志
AgentRun 执行记录
错误码统计
慢查询记录
第三方接口调用耗时
AI 调用耗时和失败原因
```

Agent 类任务必须能追踪：

```text
输入来源
使用的 Prompt 版本
使用的模型
输出结构校验结果
风险标记
用户反馈
```

## 9. 代码审查门槛

以下情况不得合并：

- 控制器里堆大量业务逻辑。
- 一个文件承担多个模块职责。
- 缺少权限判断。
- 缺少关键错误处理。
- 缺少核心路径测试。
- 新增接口响应格式不统一。
- 新增状态或枚举没有集中定义。
- 查询没有分页或可能全表扫描。
- 日志输出敏感数据。
- AI 输出没有结构化校验。

## 10. 阶段说明要求

后端、AI、向量库、记忆、召回、压力测试等关键阶段，每推进一步都必须向用户说明：

```text
这一步做了什么
用了哪些技术点
为什么这么选
难点是什么
风险在哪里
如何测试和验证
下一步是什么
```

这是项目协作规则，不是可选说明。
